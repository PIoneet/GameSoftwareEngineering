# Resource — 그래픽 리소스

"잠든 것의 이름" 의 메쉬 · 스켈레톤 · 애니메이션. **Blender 스크립트로 생성한다.**

> **이 폴더의 범위:** 리소스와 그 생성 도구까지. 게임 코드(`SimpleGame/`)는 건드리지 않는다.
> 로더가 알아야 할 약속은 전부 [`FORMAT.md`](FORMAT.md) 에 적어 두었다.

---

## 1. 빌드

Blender **5.2.2 LTS** 로 실제로 구워서 확인했다 (`C:\Program Files\Blender Foundation\Blender 5.2`).

```bash
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" --background --factory-startup --python tools/build_all.py
```

약 15초. `export/` (3.6 MB) · `blend/` (3.1 MB) · `data/` (84 KB) 가 전부 다시 만들어진다.

### 검증 — 둘 다 Blender 없이 돈다

```bash
python tools/check.py           # 굽기 전 정의
python tools/verify_export.py   # 구워진 결과
```

`check.py` 는 좌표·본 이름 오타·폴리곤 예산·4족 보행 순서·정점 색 범위를 본다.
`verify_export.py` 는 구워진 glTF 가 [`FORMAT.md`](FORMAT.md) 1절의 기능 범위를
벗어나지 않았는지, 클립 길이가 문서와 맞는지, 색이 팔레트대로 복원되는지를 본다.

**둘은 보는 것이 다르다.** 정의가 맞아도 내보내기 설정 하나로 결과가 틀어질 수 있다 —
실제로 정점 색이 두 벌로 나가거나 통째로 빠진 적이 있고, 그건 `check.py` 로는 못 잡는다.

## 3. 무엇이 들어 있나

### 3-1. 캐릭터 — 7등신, 레고식 조립

키 1.75 m = 머리 7개. **파츠 31 종**이 12개 슬롯에 들어간다.

| 슬롯 | 파츠 |
|---|---|
| head | 둥근 / 각진 / 길쭉한 |
| face | 보통 / 수염 / 노인 |
| hair | 짧은 / 긴 / 쪽진 |
| torso | 튜닉 / 로브 / 가죽조끼 / 앞치마 |
| arms | 맨팔 / 소매 / 팔보호대 |
| hands | 맨손 / 장갑 |
| legs | 바지 / 맨다리 / 정강이받이 |
| feet | 신발 / 장화 |
| cloak | 짧은망토 / 후드망토 |
| belt | 허리띠 / 주머니벨트 |
| headgear | 두건 / 모자 / 투구 |
| backpack | 배낭 |

**핵심 — 파츠를 갈아끼워도 릭은 하나다.** 모든 파츠가 같은 아마튜어에 스키닝되어
있어서 "조립" 은 어느 메쉬를 그릴지 고르는 문제일 뿐이다. 애니메이션은 그대로 돈다.

기존 `SimpleGame/Actors.cpp` 의 NPC 14명 + 플레이어에 맞춰 **프리셋 15명**을 적어 두었다
(`data/character_parts.json` 의 `presets`). 색 인덱스도 `LOOKS` 표와 짝이 맞는다.

기본 조합 **676 삼각형** (예산 1,800).

### 3-2. 짐승 — 4족, 뒷다리가 핵심

| 종 | 과 | 식성 | 성향 | 어깨높이 |
|---|---|---|---|---|
| 겨울이빨늑대 | 개과 | 육식 | **위험** | 0.85 m |
| 폐허표범 | 고양이과 | 육식 | **위험** | 0.78 m |
| 오염된 늑대 | 개과 | 육식 | **위험** | 0.95 m |
| 숲살쾡이 | 고양이과 | 육식 | 중립 | 0.50 m |
| 큰뿔사슴 | 사슴과 | 초식 | 중립 | 1.30 m |
| 마을개 | 개과 | 육식 | 순함 | 0.55 m |
| 붉은사슴 | 사슴과 | 초식 | 순함 | 1.05 m |

뒷다리는 **5단**이다 — `thigh → shin → hock → metatarsus → hindtoe`.
사람 다리를 네 개 쓰면 짐승이 되지 않는다. 뒤로 꺾인 비절(`hock`)이 지면에서 떠 있는
것이 포유류 뒷다리의 전부다. 과의 차이도 결국 이 비율이다:

```
중족골 길이   사슴 0.340  >  개 0.260  >  고양이 0.220      (어깨높이 1.0 기준)
             제행(발굽)      지행           지행·발바닥 넓음
```

**과마다 파일 하나, 종은 그 안의 조합**이다. 늑대와 마을개는 뼈대가 같으니
파일을 나눌 이유가 없다 — 크기(`scale`)와 털색, 켜는 파츠만 다르다.
릭은 어깨높이 1.0 m 로 굽혀 있고 종별 크기는 게임이 균일 스케일로 맞춘다.

`taint` 파츠를 켜면 어느 짐승이든 오염 개체가 된다. 새 모델이 필요 없다.

짐승 한 마리 **832~868 삼각형** (예산 1,200).

### 3-3. 주거 환경 — 2 m 격자 조립

벽 한 장이 정확히 한 칸(2.0 m)을 채운다. 나란히 놓기만 하면 틈이 없다.

```

가구   9종  탁자 · 긴의자 · 등받이없는의자 · 침대 · 궤 · 선반 · 통 · 나무상자 · 찬장
도구  11종  두레박 · 등불 · 가마솥 · 모루 · 바구니 · 자루 · 밧줄 · 사다리 · 수레바퀴 · 간판 · 빗자루

`data/prop_catalog.json` 에 **조립 청사진** 둘을 예시로 넣어 두었다 (작은 오두막, 여관 1층).

```

## 4. 읽어 둘 결정 세 가지

### 4-1. 포맷은 glTF 2.0, OBJ 는 안 쓴다

OBJ 는 **스켈레톤도 애니메이션도 못 담는다.** 게다가 `.gitignore:78` 의 `*.obj`
(C++ 오브젝트 파일 규칙)에 걸려 **커밋조차 되지 않는다.**
`Dependencies/x64/` 가 통째로 사라졌던 2026-09-14 사고와 같은 패턴이라 미리 확인했다.
`.gltf` · `.bin` · `.blend` · `.json` 은 전부 정상 추적된다.

### 4-2. 텍스처를 쓰지 않는다

UV 도 이미지도 만들지 않는다. 색은 머티리얼 `baseColorFactor` 와 정점 색으로만 들어간다.
**로더에 이미지 디코더가 필요 없다** — 텍스처 로딩·밉맵·아틀라스가 통째로 없어진다.
로우폴리 플랫 셰이딩이라 화질 손해도 거의 없다.

색 교체는 머티리얼 **이름**으로 한다. `slot.skin`, `slot.cloth_main`, `slot.fur_main` …
로더는 `slot.` 으로 시작하는 머티리얼의 색만 인스턴스 값으로 갈아끼우면 된다.
지금 코드의 `Model.h` `ColorSlot` 과 같은 발상이다.

### 4-3. 루트 모션이 없다

이동 클립은 전부 제자리다. 이동은 게임이 하고, 클립은 "원래 어느 속도를 가정했는가"
(`speed_mps`)만 들고 있다. **walk 와 run 의 접지 위상을 0.0 으로 맞춰 두었으므로
정규화 위상을 공유한 채 섞으면 발이 미끄러지지 않는다.**

```
phase += dt / lerp(walk.duration, run.duration, blend);
phase  = fmod(phase, 1.0);
pose   = lerp( sample(walk, phase), sample(run, phase), blend );
```

`turn_L/R` 은 몸통을 **25도만** 비튼다. 실제 방향 전환은 게임이 yaw 를 보간해서 한다 —
클립이 90도를 돌아 버리면 두 배로 돌아간다. 모든 클립이 `base` 포즈에서 시작해
`base` 로 끝나므로 도중에 끊겨도 포즈가 튀지 않는다.

## 5. 주의 — 지금 렌더러와 충돌하는 지점

`CLAUDE.md` 4-1 의 **"깊이 = `x + y`, `z` 는 화면 Y 만 민다"** 는 2D 스프라이트 전제다.
3D 메쉬를 쓰면 실제 깊이 버퍼가 필요하고 그 규약은 더 이상 성립하지 않는다.
**"깊이 테스트는 끈다"** 도 마찬가지다.

이 폴더는 리소스만 책임진다. 렌더러를 어디까지 바꿀지는 코드 작업에서 정할 일이고,
그때 쓸 수 있도록 좌표계·단위·축 변환을 [`FORMAT.md`](FORMAT.md) 2절에 적어 두었다.

## 6. 색 — 기존 코드에서 가져왔다

세계관의 색감은 이미 코드 안에 있었다. 그걸 출처로 삼았다.

| 출처 | 가져온 것 |
|---|---|
| `Draw.cpp:305-313` | 타일 색 8종 → 땅 재질 |
| `Actors.cpp:67-89` | NPC 15명의 망토/피부/머리 → 캐릭터 색 슬롯 |
| `Game.cpp:1757` | 배경 `0.026, 0.032, 0.044` → 밤의 기준 |
| `Game.cpp:1828` | 등불 `0.98, 0.72, 0.36` → 따뜻한 극 |
| `Game.cpp:1840` | 이계 청록 `0.24, 0.92, 0.84` → 차가운 극 |

**다만 그대로 쓰지 않았다.** 기존 값은 "어두운 화면에 그대로 찍히는 최종 색" 이다.
3D 알베도로 쓰면 거기에 조명이 또 곱해져 **전부 까맣게 죽는다.**
그래서 명도만 올리고 색상·채도 관계는 원본 그대로 뒀다 (`common/palette.py` 머리말).

`ELDRITCH` 청록은 아껴 쓴다. 흔해지면 "이상함" 이 전달되지 않는다.

## 7. 고칠 때

- **좌표는 `rig_*.py` 의 `JOINTS` 가 유일한 출처다.** 메쉬 쪽에 숫자를 새로 적지 않는다 —
  적는 순간 뼈와 살이 어긋나고, 팔을 들면 소매가 어깨에서 떨어진다.
- **본 길이는 바꾸지 않는다.** 바꾸면 애니메이션을 공유할 수 없다. 체형 변주는
  `rig_humanoid.BUILDS` 처럼 **메쉬 두께**로만 준다.
- 새 머티리얼은 `palette.MATERIALS` 에 먼저 추가한다. 없는 이름을 쓰면 즉시 `KeyError` 가
  난다 — 조용히 흰색으로 빠지는 것보다 낫다.
- 고치고 나면 **반드시 `python tools/check.py`.** Blender 를 켜기 전에 대부분 잡힌다.
- `data/*.json` 은 생성물이다. 손으로 고치면 다음 빌드에 날아간다.
